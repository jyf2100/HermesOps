### Phase 3: 逐个升级 Gateway（预计 30-60 分钟）

**关键原则**: 逐个升级，每次只动 1 个 gateway，验证后再继续。
**数据安全**: Gateway 数据在 hostPath `/data/hermes/agent{N}/`，升级 deployment 不影响数据。

对每个 gateway N (1-13):

```bash
# 3a. 在 184 上，通过 admin API 升级 gateway
ADMIN_KEY=$(sudo kubectl get secret hermes-admin-secret -n hermes-agent -o jsonpath='{.data.admin_key}' | base64 -d)

# 先获取当前 agent 信息
AGENT_INFO=$(curl -s http://172.32.153.183:40080/admin/api/agents/$N \
  -H "X-Admin-Key: $ADMIN_KEY")

# 3b. 删除旧 gateway（保留数据目录）
curl -s -X DELETE "http://172.32.153.183:40080/admin/api/agents/$N?backup=true" \
  -H "X-Admin-Key: $ADMIN_KEY"

# 3c. 用新模板重建 gateway（三容器架构）
# 需要从旧 agent 信息中提取 display_name, tags, role, provider, model 等
# 通过 admin API 重建
curl -s -X POST "http://172.32.153.183:40080/admin/api/agents" \
  -H "X-Admin-Key: $ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "agent_number": '$N',
    "display_name": "...",
    "provider": "...",
    "model": "...",
    "api_key": "...",
    "tags": [...],
    ...
  }'
```

**注意**: 由于 gateway 配置（provider, model, api_key）存在每个 agent 的 `.env` 文件中
（`/data/hermes/agent{N}/.env`），删除 deployment 不会删除这些文件。重建后可复用。

### Phase 5: 更新 Ingress（预计 5 分钟）

`_ensure_agents_ingress()` 在每次 create/delete agent 时自动更新。
如果使用 admin API 重建，ingress 会自动包含:
- `/agent{N}(/|$)(.*)` → gateway:8642
- `/agent{N}/ops(/|$)(.*)` → gateway:6060

nip.io WebUI Ingress 也由 admin 自动创建:
- `agent{N}.172-32-153-183.nip.io` → hermes-webui-{N}:6060

手动验证:
```bash
ssh root@172.32.153.183
kubectl get ingress hermes-agents-ingress -n hermes-agent -o yaml | grep "path:"
# 应该看到每个 agent 的两个路径
```

## 四、关键风险与缓解

| # | 风险 | 等级 | 缓解措施 |
|---|------|------|---------|
| 1 | Gateway 升级中断正在进行的对话 | 🟡 中 | 逐个升级，非高峰时段执行 |
| 2 | 用户 DC API key 失效 | 🟡 中 | Phase 6 自动 re-provision |
| 3 | 数据库 schema 不兼容 | 🟢 低 | 旧 plan 已验证 schema 一致；新表自动迁移 |
| 4 | 资源不足（13×3 容器 + 13 WebUI） | 🟡 中 | 96C/502G 节点，requests 可调整 |
| 5 | ops-panel 镜像不存在 | 🟢 低 | 使用相同 hermes-agent 镜像的 sidecar |
| 6 | nip.io DNS 不可达 | 🟢 低 | 独立 WebUI 通过 nip.io 访问，内网可达 |
| 7 | Ingress 路由冲突 | 🟢 低 | admin 的 `_ensure_agents_ingress()` 自动管理 |
| 8 | hostPath 数据丢失 | 🟢 低 | 只删 deployment 不删数据目录 |

### 资源预估
